### 一、设计原则

1. **合同编号即项目标识** — `contract_no` 是项目的唯一标识，前项和后项合同共享同一个 `contract_no`
2. **项目级信息统一管理** — 地市、负责人、项目名称只存在 `projects` 表，其他表通过 `contract_no` 关联获取
3. **UUID 主键** — 所有业务表使用 UUID 作为主键，避免自增 ID 暴露数据量
4. **时间戳标准化** — 统一使用 `TIMESTAMPTZ` 类型，统一字段名 `created_at` / `updated_at`

### 三、表结构

#### 3.1 `projects` — 项目表

合同编号即项目标识。Agent 在处理首份合同时，若 `contract_no` 不存在则自动创建项目记录。

| 字段 | 类型 | 约束 | 说明 |
|:---|:---|:---|:---|
| contract_no | VARCHAR(100) | PK | 合同编号，同时也是项目唯一标识 |
| project_name | VARCHAR(200) | | 项目名称 |
| city | VARCHAR(20) | | 地市 |
| responsible_person | VARCHAR(50) | | 项目负责人 |
| status | VARCHAR(20) | DEFAULT '待审查' | 待审查 / 审查中 / 已完成 |
| risk_level | VARCHAR(10) | | 高 / 中 / 低 |
| created_at | TIMESTAMPTZ | DEFAULT now() | |
| updated_at | TIMESTAMPTZ | DEFAULT now() | |

**索引**：无额外索引（PK 自带唯一索引）

---

#### 3.2 `contracts` — 合同表

每笔合同记录（前项或后项），通过 `contract_no` 关联到项目。项目级信息通过 JOIN `projects` 获取，不在本表冗余。

| 字段 | 类型 | 约束 | 说明 |
|:---|:---|:---|:---|
| id | UUID | PK | DEFAULT gen_random_uuid() |
| contract_no | VARCHAR(100) | FK → projects(contract_no) | 关联项目 |
| contract_type | VARCHAR(10) | NOT NULL | 前项 / 后项 |
| type_judge_basis | VARCHAR(200) | | 前后项判定依据 |
| party_a | VARCHAR(200) | | 甲方 |
| party_b | VARCHAR(200) | | 乙方 |
| our_role | VARCHAR(10) | | 我方角色：甲方 / 乙方 |
| signing_date | DATE | | 签约日期 |
| contract_period | VARCHAR(100) | | 工期描述 |
| total_amount | DECIMAL(14,2) | | 合同总金额（元）|
| amount_uppercase | VARCHAR(100) | | 大写金额 |
| tax_rate | DECIMAL(5,4) | | 税率 |
| payment_terms | TEXT | | 付款条款 |
| delivery_terms | TEXT | | 交付条款 |
| acceptance_terms | TEXT | | 验收条款 |
| breach_terms | TEXT | | 违约责任 |
| warranty_terms | TEXT | | 质保条款 |
| ip_terms | TEXT | | 知识产权条款 |
| other_key_terms | TEXT | | 其他关键条款 |
| source_file_id | UUID | FK → source_files(id) | 关联原始文件 |
| source_file_name | VARCHAR(300) | | 原始文件名 |
| source_file_hash | VARCHAR(64) | | SHA256，防重复上传 |
| ocr_raw_text | TEXT | | OCR 原始识别文本（默认不返回）|
| ocr_engine | VARCHAR(20) | | OCR 引擎名 |
| llm_model | VARCHAR(50) | | LLM 模型名 |
| verified | BOOLEAN | DEFAULT false | 是否人工确认 |
| verified_by | VARCHAR(50) | | 确认人 |
| verified_at | TIMESTAMPTZ | | 确认时间 |
| extracted_at | TIMESTAMPTZ | | 提取时间 |

| updated_at | TIMESTAMPTZ | DEFAULT now() | |


### 四、索引策略

| 表 | 索引名 | 字段 | 理由 |
|:---|:---|:---|:---|
| contracts | idx_contracts_no | contract_no | 按合同编号检索合同列表 |
| contracts | idx_contracts_type | (contract_no, contract_type) | 按项目+类型查询前后项配对 |
| line_items | idx_line_items_contract | contract_id | 按合同查询分项清单 |
| acceptance_reports | idx_acceptance_contract | contract_no | 按项目查询验收报告 |

### 五、命名规范

| 项目 | 规范 | 示例 |
|:---|:---|:---|
| 表名 | 小写+下划线，复数 | `line_items`, `risk_records` |
| 字段名 | 小写+下划线 | `contract_no`, `payment_terms` |
| 主键 | `id` | UUID |
| 外键 | `{关联表名}_id` | `contract_id`, `source_file_id` |
| 索引 | `idx_{表}_{字段}` | `idx_contracts_no` |
| 时间字段 | `{描述}_at` | `created_at`, `verified_at` |
| JSON 字段 | `{描述}` | `detail` |

### 六、迁移策略

使用 Alembic 进行数据库版本管理：

```
backend/app/db/migrations/
├── versions/             # 迁移脚本
│   ├── 0001_initial.py  # 初始建表
│   └── ...
├── env.py               # Alembic 环境配置
└── alembic.ini          # 配置文件
```

**原则**：
- 每次 schema 变更创建新的迁移脚本
- 迁移脚本必须可回滚（`downgrade()`）
- 不修改已发布的迁移脚本（除非未上线）
- 开发环境可自动迁移，生产环境手动执行

### 七、查询频率分析

| 查询模式 | 频率 | 涉及表 | 说明 |
|:---|:---|:---|:---|
| 合同列表（分页） | 高频 | contracts + projects | 默认查询 |
| 合同详情 | 高频 | contracts + line_items | 单条查询 |
| 比对结果列表 | 中频 | comparisons + projects | 按合同编号检索 |
| 报表聚合 | 低频 | comparisons / acceptance | 按地市聚合 |
| 风险看板 | 中频 | risk_records | 按等级+状态筛选 |
| 仪表盘 | 高频 | 多表聚合 | 简单 COUNT 查询 |
