## 文档规范清单

> 本文档定义每个文档的结构规范，所有文档必须严格遵循。
> 编号规则：00=总纲，01-03=需求，04-07=设计，08+=其他流程。

---

### 一、文档通用规范

| 项目 | 要求 |
|:---|:---|
| 格式 | Markdown，UTF-8 编码 |
| 标题 | 一级标题 `##` 开头（跳过 `<h1>` 作为文件标题） |
| 章节 | 二级标题 `###` 开始，最多四级 `####` |
| 修订记录 | 每个文档首部含版本/日期/修订人/内容表格 |
| 引用已有 | 不重复其他文档已有内容，只引用 |
| 术语一致 | `contract_no`=合同编号，`前项/后项`=合同类型 |

修订记录模板：

```
| 版本 | 日期 | 修订人 | 修订内容 |
|:---|:---|:---|:---|
| V1.0 | 2026-07-01 | — | 初始版本 |
```

---

### 二、各文档规范

#### 01. 用户需求

| 项目 | 要求 |
|:---|:---|
| 定位 | 业务方的原始需求，开发/测试的输入依据 |
| 章节 | 项目背景 → 业务目标 → 功能需求 → 数据维度 → 用户角色 |
| 粒度 | 功能需求按模块列出，不展开细节 |
| 语言 | 业务语言，不含技术实现 |

---

#### 02. 技术选型

| 项目 | 要求 |
|:---|:---|
| 定位 | 各技术选项的对比和决策记录 |
| 章节 | 决策摘要表 → 逐项对比（评估维度/候选方案/结论）→ 其他选型 |
| 粒度 | 每个选型包含：候选方案、对比维度表、决策理由 |
| 篇幅 | 每项选型不超过 1 页，不展开架构理念 |

---

#### 03. 需求规格说明书

| 项目 | 要求 |
|:---|:---|
| 定位 | 功能的具体规则、字段、交互、边界条件，开发/测试的共同依据 |
| 章节 | 概述 → 功能模块（每个模块：功能描述 → 字段 → 规则 → 异常场景）→ 非功能性需求 → 约束 |
| 粒度 | 每个功能点包含：输入、处理逻辑、输出、字段规则、判定规则、异常场景 |
| 数据口径 | 报表必须注明数据来源和聚合规则 |

---

#### 04. 项目整体设计构思

| 项目 | 要求 |
|:---|:---|
| 定位 | 架构、表设计、API 设计、业务流程、部署方案的总纲 |
| 章节 | 架构图 → 设计原则 → 数据库 DDL → API 路径表 → 流程说明 → 技术选型表 → 目录结构 → 部署方案 → 非功能性需求 |
| 粒度 | DDL 必须完整（含索引），API 至少包含路径/方法/功能 |
| 地位 | 该文档为技术总纲，其他设计文档（05-07）是其展开 |

---

#### 05. 数据库设计文档

| 项目 | 要求 |
|:---|:---|
| 定位 | 数据库的完整设计说明 |
| 章节 | ER 关系图 → 表结构（字段/类型/约束/说明）→ 索引策略 → 命名规范 → 迁移策略 |
| 粒度 | 每个字段必须包含：类型、约束、说明 |
| 与 04 关系 | 从 04 的 DDL 展开，补充 ER 关系和字段说明，两者一致 |

---

#### 06. 接口设计文档

| 项目 | 要求 |
|:---|:---|
| 定位 | 前后端联调依据 |
| 章节 | 通用规范（Base URL/认证/响应格式/分页）→ 接口明细（按模块） |
| 粒度 | 每个接口包含：方法/路径、请求示例、响应示例、错误码 |
| 优先级 | 复杂接口优先，简单 CRUD 参考 Swagger |

---

#### 07. 前端设计文档

| 项目 | 要求 |
|:---|:---|
| 定位 | 前端架构、组件、状态管理方案 |
| 章节 | 技术栈 → 目录结构 → 路由 → 组件设计 → 状态管理 → Axios 封装 → 页面布局 |
| 粒度 | 组件注明 Props/Events，页面附布局图 |
| 约定 | 不与 06 重复接口定义，只引用 |

---

#### 08. 工作流程描述

| 项目 | 要求 |
|:---|:---|
| 定位 | 端到端业务流程说明，面向新成员和业务方 |
| 章节 | 阶段划分 → 每阶段：输入/操作/输出/判定规则 → 关键决策点 → 全流程总图 |
| 粒度 | 每个阶段包含：操作人、输入文件、处理步骤、产出结果 |
| 语言 | 半业务半技术，新成员可看懂 |
