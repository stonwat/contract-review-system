### 二、后端框架：FastAPI vs Spring Boot

#### 2.1 评估维度

| 维度 | FastAPI (Python) | Spring Boot (Java) |
|:---|:---|:---|
| LLM/OCR 生态 | 原生支持，import 即用 | 需包 JNI 或调外部进程 |
| 技术栈一致性 | 与本地 Agent（Python）一致，共享数据结构 | 两端两门语言，增字段改两处 |
| 开发效率 | 一个 CRUD 接口 5 分钟，热重载 | Controller/Service/Repository 六件套 |
| 运行时性能 | 异步 ASGI，够用 | 高并发更强，本项目用不上 |
| 学习成本 | 团队已有 Python 经验 | 需 Java 体系经验 |
| 部署体积 | 轻量，~200MB 镜像 | 较重，~500MB+ 镜像 |

#### 2.2 结论

本项目后端计算密集度不高（主要是 SQL 查询 + LLM 调用），高并发不是瓶颈。Python 在 LLM/OCR 生态和开发效率上有明显优势，选择 **FastAPI**。

### 三、数据库：PostgreSQL

#### 3.1 评估

| 需求 | PostgreSQL | MySQL | 说明 |
|:---|:---|:---|:---|
| JSONB 支持 | 原生 | JSON 功能较弱 | 后续扩展字段/分析结果附件用 JSONB |
| DECIMAL 精度 | 精确 | 精确 | 金额计算 |
| 全文搜索 | 内置 | 需额外配置 | 后续搜索扩展 |
| CTE 递归 | 支持 | 8.0+ 支持 | 复杂报表查询 |

#### 3.2 结论

选择 **PostgreSQL 16**，主要考虑 JSONB 和精确数值计算能力。

### 四、前端：Vue 3 + TypeScript + Element Plus

#### 4.1 框架选型

| 维度 | Vue 3 | React |
|:---|:---|:---|
| 学习成本 | 较低，模板语法直观 | 较高，JSX + hooks |
| 组件库生态 | Element Plus 完善 | Ant Design 完善 |
| TypeScript | 组合式 API + TS 支持好 | 原生支持 |
| 团队经验 | 已有经验 | 无 |

选择 **Vue 3 + TypeScript**。

#### 4.2 UI 组件库

| 维度 | Element Plus | Ant Design Vue | naive-ui |
|:---|:---|:---|:---|
| 表格能力 | Table 完善，支持筛选/排序/分页 | 类似 | 较新，生态不如前两者 |
| 表单能力 | Form 校验完善 | 完善 | 完善 |
| 社区活跃度 | 最高 | 较高 | 较低 |
| 项目匹配度 | 管理后台场景成熟 | 偏中后台 | 偏轻量 |

选择 **Element Plus**，管理后台的表格/表单/弹窗场景最成熟。

#### 4.3 样式方案

- 主 UI 由 Element Plus 组件提供，样式按组件文档走
- TailwindCSS 仅用于间距、布局等微调，不作为主样式方案
- 不引入 CSS Modules 或 styled-components

### 五、文件存储：MinIO

#### 5.1 评估

| 维度 | MinIO | 本地文件系统 | 对象存储云服务 |
|:---|:---|:---|:---|
| 部署复杂度 | Docker 一键部署 | 无需部署 | 需网络/账号 |
| S3 兼容 | 原生 | 不兼容 | 原生 |
| 迁移性 | 可无缝迁移到云 S3 | 迁移成本高 | 绑定厂商 |

#### 5.2 结论

选择 **MinIO**，后续上云可无缝切换到任何 S3 兼容服务。

### 六、任务队列：Redis + arq

| 维度 | Redis + arq | Celery | RabbitMQ |
|:---|:---|:---|:---|
| 轻量级 | 是 | 较重 | 重 |
| 异步支持 | 原生 async/await | 需配置 | 需配置 |
| 部署依赖 | Redis 已纳入 docker-compose | 需 Redis/RabbitMQ | 需 Erlang 环境 |

本项目异步任务简单（LLM 提取与对比分析），无需 Celery 的复杂度。选择 **Redis + arq**。

---

### 七、OCR：PaddleOCR

PaddleOCR 已有项目经验（已有 paddleocr-doc-parsing Skill），识别效果好，支持中英文混合场景。Agent 本地运行，不占用服务端资源。

---

### 八、LLM：可配置

| 场景 | 模型要求 | 配置方式 |
|:---|:---|:---|
| 合同字段提取 | 需支持 JSON 结构化输出 | 环境变量 `LLM_MODEL` |
| 验收报告字段提取 | 需支持 JSON 结构化输出 | 环境变量 `LLM_MODEL` |
| 前后项合同对比分析 | 需理解合同条款语义，计算毛利率并判定一致性 | 环境变量 `LLM_API_KEY`、`LLM_BASE_URL` |
| 前后项验收报告对比分析 | 需理解验收内容语义，判定一致性 | 环境变量 `LLM_API_KEY`、`LLM_BASE_URL` |

不绑定具体模型厂商，通过环境变量配置，提取和分析可用不同模型。
