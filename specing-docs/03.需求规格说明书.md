### 一、概述

#### 1.1 项目背景

审查人员需要人工比对工程项目的前项合同（业主与施工方签订）和后项合同（施工方与分包方签订）之间的差异，包括金额、条款等。当项目数量达数百个时，人工比对工作量极大，且容易遗漏风险。本系统旨在通过 OCR + LLM 自动提取合同与验收报告信息，由 LLM 完成前后项对比分析，判定项目风险，生成统计报表。

#### 1.2 业务术语

| 术语 | 说明 |
|:---|:---|
| 前项合同 | 业主与施工方签订的原始合同 |
| 后项合同 | 施工方与实际分包方签订的分包合同 |
| 合同编号 | 用于标识同一项目前后项合同的唯一编号（`contract_no`） |
| 毛利率 | (前项金额 - 后项金额) / 前项金额 |
| 材料完整性 | 项目是否齐全前项合同、后项合同、前项验收、后项验收四类材料（`has_*` 布尔标记） |
| LLM 分析 | 对前后项合同/验收报告进行对比分析，产出毛利率、一致性、分析文本 |
| 项目风险 | 基于 LLM 分析结果综合判定的 `project_risk`（低风险/高风险） |

#### 1.3 用户角色

| 角色 | 角色代码 | 说明 |
|:---|:---|:---|
| 超级管理员 | `super_admin` | 系统最高权限，开通账号、管理角色、操作所有地市数据、删除数据 |
| 省市管理员 | `city_admin` | 绑定一个地市，确认/操作该地市项目，可导出报表 |
| 只读用户 | `viewer` | 全局只读浏览，不可确认、不可导出、不可修改 |
| Agent | — | 自动化处理端，负责 OCR 识别和 LLM 提取/分析，通过 API Key 认证 |

##### 1.3.1 权限矩阵

| 操作 | super_admin | city_admin | viewer |
|:---|:---:|:---:|:---:|
| 浏览所有页面和数据 | ✅ | ✅（全局只读+本省市可操作） | ✅（全局只读） |
| 确认合同（verify） | ✅ 所有地市 | ✅ 仅本省市 | ❌ |
| 确认验收报告（verify） | ✅ 所有地市 | ✅ 仅本省市 | ❌ |
| 确认分析结果（verify） | ✅ 所有地市 | ✅ 仅本省市 | ❌ |
| 确认项目审查状态 | ✅ 所有地市 | ✅ 仅本省市 | ❌ |
| 编辑合同/验收字段 | ✅ 所有地市 | ✅ 仅本省市 | ❌ |
| 导出报表 | ✅ 所有地市数据 | ✅ 仅本省市数据 | ❌ |
| 开通/管理账号 | ✅ | ❌ | ❌ |
| 删除合同/验收/项目 | ✅ | ❌ | ❌ |
| 重置项目分析状态 | ✅ | ❌ | ❌ |

##### 1.3.2 地市数据隔离规则

`city_admin` 的操作隔离边界：

- **可操作**：`projects.city` 等于 `city_admin.city` 的项目，包括该项目的合同确认/编辑、验收报告确认/编辑、分析结果确认、审查状态更新、导出本省市报表
- **不可操作**：`projects.city` 不等于 `city_admin.city` 的任何数据
- **可浏览**：所有地市的数据（只读），包括项目列表、合同详情、分析结果等查看

`super_admin` 和 `viewer` 无地市限制（`city` 字段为 NULL）。

地市枚举（黑龙江省 13 个地级市）：

```
哈尔滨, 齐齐哈尔, 牡丹江, 佳木斯, 大庆, 鸡西, 双鸭山,
伊春, 七台河, 鹤岗, 黑河, 绥化, 大兴安岭
```

> 地市值与 `projects.city` 存储格式一致（不带"市"后缀）。

### 二、功能模块

#### 2.1 仪表盘

##### 2.1.1 功能描述

系统总览页面，展示关键指标的统计数据，帮助审查人员快速了解整体情况。

#### 2.4 合同对比分析（LLM）

##### 2.4.1 功能描述

由 LLM 对同一项目的前项和后项合同进行对比分析，包括毛利率计算、条款一致性判定、分析文本生成。结果存入 `contract_analysis` 表。

##### 2.4.2 触发条件

- 项目材料齐全：`has_front_contract`、`has_back_contract`、`has_front_acceptance`、`has_back_acceptance` 四个布尔字段全为 `true`
- 由用户在 Agent 对话中明确指令触发（如"进行项目风险分析"），**不自动触发**
- 支持重新分析：用户对已有结果不满意时可重置 `llm_analyzed=false` 重新触发

##### 2.4.3 分析结果字段

| 字段 | 说明 |
|:---|:---|
| 合同编号 contract_no | 所属项目 |
| 毛利率 rate | (前项金额 - 后项金额) / 前项金额 |
| 毛利率等级 rate_level | 正常 / 低毛利 / 利润倒挂 |
| 条款一致性 similarity | 完全一致 / 有一致性风险 / 完全不一致 |
| 分析文本 analysis | LLM 生成的差异与风险点描述 |
| 确认状态 verified | 待确认 / 已确认 |

##### 2.4.4 判定规则

**毛利率等级**：

| 条件 | 等级 |
|:---|:---|
| rate < 0 | 利润倒挂 |
| 0 ≤ rate < 0.05 | 低毛利 |
| rate ≥ 0.05 | 正常 |

**条款一致性**：

| 取值 | 含义 |
|:---|:---|
| 完全一致 | 条款无差异 |
| 有一致性风险 | 部分条款存在差异 |
| 完全不一致 | 关键条款严重偏离 |

##### 2.4.5 覆盖式更新

- 每个项目在 `contract_analysis` 表只有一条记录
- 重新分析时 UPDATE 覆盖，`updated_at` 自动刷新，`verified` 重置为 `false`

##### 2.4.6 人工确认

- LLM 分析结果可能出错（毛利率算反、一致性判断有误），需人工确认
- 确认后才用于最终项目风险判定

##### 2.4.7 异常场景

| 场景 | 处理方式 |
|:---|:---|
| 仅有一份合同，缺少配对 | 不满足触发条件，不分析 |
| LLM 调用超时 | 标记分析失败，不影响其他项目 |
| 毛利率计算除零 | 前项金额为 0 时 rate 标记为 null |

#### 2.6 项目风险

##### 2.6.1 功能描述

展示所有项目的风险判定结果。风险由 LLM 综合两个分析表结果自动推送至 `projects.project_risk`，无需人工录入。

##### 2.6.2 风险生成来源

| 来源 | 说明 |
|:---|:---|
| `contract_analysis` | 毛利率等级、合同条款一致性 |
| `acceptance_report_analysis` | 验收报告一致性 |
| LLM 综合判定 | 综合上述两表结果推送 `project_risk` |

##### 2.6.3 风险判定规则

| 条件 | 风险等级 |
|:---|:---|
| 利润倒挂（rate < 0） | 高风险 |
| 低毛利（0 ≤ rate < 0.05） | 高风险 |
| 任一 similarity 为"完全不一致" | 高风险 |
| 以上条件均不满足 | 低风险 |

##### 2.6.4 项目风险列表

| 字段 | 说明 |
|:---|:---|
| 合同编号 | |
| 项目名称 | |
| 地市 | |
| 项目风险 project_risk | 低风险 / 高风险 |
| LLM 分析状态 | 已分析 |
| 审查状态 audit_status | 待审查 / 已完成 |
| 操作 | 查看分析详情 / 完成审查 |

##### 2.6.5 筛选条件

- 按项目风险筛选（全部 / 低风险 / 高风险）
- 按地市筛选
- 按审查状态筛选

##### 2.6.6 异常场景

| 场景 | 处理方式 |
|:---|:---|
| 项目未分析 | `project_risk` 为空，显示"未分析"，不参与风险列表 |
| 分析结果未人工确认 | 可查看但标注"待确认"状态 |

2. 服务端校验后返回 JWT token
3. 前端存储 token，后续请求携带
4. Token 有效期 24 小时

**错误处理**：
- 用户名不存在：返回"用户名或密码错误"（不具体提示哪个不对）
- 密码错误：同上
- 账号已禁用：返回"账号已被禁用，请联系管理员"

##### 2.8.3 账号管理

> 仅 `super_admin` 可访问账号管理页面。

| 功能 | 说明 |
|:---|:---|
| 账号列表 | 展示所有账号，含角色、绑定地市、启用状态 |
| 新增账号 | 填写用户名、密码、显示名、角色（super_admin/city_admin/viewer）、绑定地市（仅 city_admin 需填） |
| 修改账号 | 可修改角色、绑定地市、显示名、启用/禁用 |
| 重置密码 | 超级管理员可重置他人密码 |
| 启用/禁用 | 禁用后无法登录 |
| 删除账号 | 不可删除自己；系统至少保留一个 super_admin |

**角色约束**：
- `city_admin` 角色必须选择一个绑定地市
- `super_admin` 和 `viewer` 角色不绑定地市
- 创建/修改时校验以上规则

### 三、非功能性需求

#### 3.1 安全性

| 要求 | 说明 |
|:---|:---|

| SQL 注入 | 通过 ORM 参数化查询 |
| 敏感配置 | .env 文件不提交 Git |

#### 3.2 性能

| 要求 | 说明 |
|:---|:---|
| 列表接口 | 必须分页，不允许全量查询 |
| LLM 调用 | 异步执行，不阻塞 API 响应 |
| 报表查询 | 大数据量下考虑缓存，不实时全量计算 |

#### 3.3 可用性

| 要求 | 说明 |
|:---|:---|
| 服务端无状态 | 支持水平扩展 |
| 数据库建表 | 暂不使用 Alembic 迁移工具，表结构由 ORM 模型创建（`Base.metadata.create_all`） |
