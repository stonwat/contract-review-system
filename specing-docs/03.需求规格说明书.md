### 一、概述

#### 1.1 项目背景

审查人员需要人工比对工程项目的前项合同（业主与施工方签订）和后项合同（施工方与分包方签订）之间的差异，包括金额、条款、分项清单等。当项目数量达数百个时，人工比对工作量极大，且容易遗漏风险。本系统旨在通过 OCR + LLM 自动提取合同信息，自动完成前后项比对，标记风险项，生成统计报表。

#### 1.2 业务术语

| 术语 | 说明 |
|:---|:---|
| 前项合同 | 业主与施工方签订的原始合同 |
| 后项合同 | 施工方与实际分包方签订的分包合同 |
| 合同编号 | 用于标识同一项目前后项合同的唯一编号 |
| 分项工程量清单 | 合同中的工程条目明细（名称、数量、单价、金额） |
| 毛利率 | (前项金额 - 后项金额) / 前项金额 |
| 高低风险 | 基于毛利率、条款一致性等指标的判定结果 |

#### 1.3 用户角色

| 角色 | 说明 |
|:---|:---|
| 管理员 | Web 端用户，可查看和管理所有数据 |
| Agent | 自动化处理端，负责 OCR 识别和 LLM 提取，通过 API Key 认证 |

##### 2.3.4 人工确认

**操作流程**：
1. 审查人员查看 Agent 提取的合同字段
2. 核对关键字段（金额、签约方、分项清单）
3. 如发现提取错误，点击编辑修正
4. 修正后点击确认，设置 `verified=true`

**修正范围**：
- 所有字段均可编辑
- 分项清单可增删改行

**规则**：
- 确认后不可直接编辑，需取消确认后才可修改
- 操作记录写入 audit_log

##### 2.3.5 触发比对

**前置条件**：
- 同一合同编号下，前项和后项合同均已确认（`verified=true`）

**操作**：
- 在合同列表或详情页点击"生成比对"
- 前端调用 `POST /api/v1/comparisons`
- 后端子创建比对结果

##### 2.3.6 异常场景

| 场景 | 处理方式 |
|:---|:---|
| OCR 文本为空 | 标记提取失败，前端显示"识别失败" |
| 金额提取异常（非数字） | 字段显示为空，人工填写 |
| 签约方提取不完整 | 人工修正 |
| 分项清单为空 | 允许手动添加 |
| 合同编号无法提取 | Agent 标记异常，前端显示"编号缺失" |

#### 2.4 合同比对

##### 2.4.1 功能描述

展示前项和后项合同的比对结果，包括金额差异、毛利率、条款语义比对结果、分项逐项比对。

##### 2.4.2 比对触发方式

| 方式 | 说明 |
|:---|:---|
| 手动触发 | 管理员在合同详情页点击"生成比对" |
| 自动检测 | 系统定时检测：已确认的前后项合同是否已比对，未比对自动触发 |

##### 2.4.3 比对结果列表

| 字段 | 说明 |
|:---|:---|
| 合同编号 contract_no | |
| 地市 | 关联项目的 city |
| 前项金额 | |
| 后项金额 | |
| 金额差异 | 前项 - 后项 |
| 毛利率 | (前项-后项)/前项 |
| 金额一致性 | 一致 / 不一致 |
| 款项一致性 | 一致 / 不一致 |
| 交付一致性 | 一致 / 不一致 |
| 验收一致性 | 一致 / 不一致 |
| 比对时间 | |

##### 2.4.4 比对详情

展示三个区域的对比结果：

**金额对比区**：
```
前项总金额：5,280,000.00
后项总金额：4,980,000.00
金额差异：   300,000.00
毛利率：     5.68%
判定：       金额一致（差异在可接受范围内）
```

**金额一致判定规则**：差异率 < 5% 视为一致。

**条款对比区**（并排或上下显示）：

| 条款 | 前项内容 | 后项内容 | 判定结果 | 差异详情 |
|:---|:---|:---|:---|:---|
| 付款条款 | ...验收后30日内支付95%... | ...验收后60日内支付90%... | 不一致 | 相差30天，比例差5% |
| 交付条款 | ... | ... | 一致 | |
| 验收条款 | ... | ... | 一致 | |
| 违约金 | ... | ... | 一致 | |
| 质保期 | ... | ... | 一致 | |

**分项对比区**：

| 分项 | 前项数量 | 后项数量 | 数量差异 | 前项单价 | 后项单价 | 单价差异 | 匹配状态 |
|:---|:---|:---|:---|:---|:---|:---|:---|
| 土建工程 | 1 | 1 | 0 | 2,000,000 | 1,850,000 | -150,000 | 精确匹配 |
| 设备采购 | 5 | 5 | 0 | 300,000 | 280,000 | -20,000 | 精确匹配 |
| 其他费用 | — | 1 | — | — | 50,000 | — | 后项独有 |

**分项匹配规则**：

```
优先按名称相似度匹配（>80% 视为同一分项）
  匹配成功后对比数量、单价、金额差异
  未匹配的列为"前项独有"或"后项独有"
  单项毛利率 = (前项金额 - 后项金额) / 前项金额
```

##### 2.4.5 比对引擎逻辑

**第一层：数值比对（服务端计算，不调LLM）**
```
金额差异 = front_total - back_total
毛利率 = (front_total - back_total) / front_total
分项匹配：按名称相似度 > 80% 配对
分项差异 = front_item_amount - back_item_amount
单项风险判定：
  利润倒挂: 毛利率 < 0%
  超量分包: back_quantity > front_quantity * 1.1
  单价倒挂: back_unit_price > front_unit_price
```

**第二层：语义比对（调LLM）**
```
付款条款 → Prompt: "判断两份合同的付款条款是否实质一致"
交付条款 → Prompt: "判断两份合同的交付条款是否实质一致"
验收条款 → Prompt: "判断两份合同的验收条款是否实质一致"
违约条款 → Prompt: "判断两份合同的违约条款是否实质一致"
```

##### 2.4.6 异常场景

| 场景 | 处理方式 |
|:---|:---|
| 仅有一份合同，缺少配对 | 不触发比对，列表显示"等待配对" |
| LLM 调用超时 | 标记该条款为"比对失败"，不影响其他条款 |
| 分项清单为空 | 显示"无分项数据"，只做总额比对 |
| 毛利率计算除零 | 前项金额为 0 时毛利率标记为"无效" |

**触发条件**：前后项验收报告均已确认

**比对内容**：
```

```

#### 2.6 风险看板

##### 2.6.1 功能描述

展示所有自动判定的风险记录，支持按等级筛选和人工忽略误报。

##### 2.6.2 风险记录生成来源

| 来源 | 说明 |
|:---|:---|
| 合同比对 | 从 `comparisons` 生成的风险 |

| 验收比对 | 从 `acceptance_reports` 生成的验收风险 |

##### 2.6.3 风险类型

| 风险类型 | 判定条件 | 风险等级 | 来源 |
|:---|:---|:---|:---|
| 利润倒挂 | 毛利率 < 0% | 高 | comparison |
| 低毛利 | 毛利率 0% ~ 3% | 高 | comparison |
| 低毛利 | 毛利率 3% ~ 5% | 中 | comparison |
| 超量分包 | 后项数量 > 前项数量 × 110% | 中 | line_item_comparison |
| 单价倒挂 | 后项单价 > 前项单价 | 高 | line_item_comparison |
| 条款不一致 | 任意条款被判不一致 | 中 | comparison |
| 验收不一致 | 验收内容判定不一致 | 高 | acceptance |
| 日期异常 | 前后项验收日期逻辑错误 | 中 | acceptance |

##### 2.6.4 风险列表

| 字段 | 说明 |
|:---|:---|
| 合同编号 | |
| 风险类型 | 参见风险类型表 |
| 风险等级 | 高/中/低 |
| 来源 | comparison / acceptance |
| 详情 | TEXT，风险的详细描述 |
| 状态 | 活跃 / 已忽略 |
| 操作 | 忽略 / 查看详情 |

##### 2.6.5 筛选条件

- 按风险等级筛选（全部 / 高 / 中 / 低）
- 按风险类型筛选
- 按状态筛选（全部 / 活跃 / 已忽略）

##### 2.6.6 忽略功能

- 管理员确认某条风险是误报后，点击忽略
- 忽略后记录 `dismissed_by` 和 `dismissed_at`
- 已忽略的风险不再出现在默认视图中
- 可取消忽略恢复

##### 2.6.7 异常场景

| 场景 | 处理方式 |
|:---|:---|
| 所有风险被忽略 | 风险看板显示"暂无风险" |
| 比对未完成 | 不生成风险记录 |

#### 2.7 报表中心

##### 2.7.1 功能描述

提供四个维度的统计报表，支持汇总查看和明细导出。

##### 2.7.2 报表一：合同内容一致性

**汇总视图**：

| 地市 | 一致对数 | 不一致对数 | 总对数 | 一致率 |

| XX市 | 15 | 3 | 18 | 83.3% |
| YY市 | 10 | 1 | 11 | 90.9% |
| 合计 | 25 | 4 | 29 | 86.2% |

- 一致率 = 一致对数 / 总对数
- 总对数 = 该地市已完成的比对数量
- 一致/不一致以 `comparisons` 中的支付/交付/验收/其他条款全部为"一致"才计数为一致

#### 2.8 管理后台

##### 2.8.1 功能描述

##### 2.8.2 登录

| 字段 | 说明 |
|:---|:---|
| 用户名 | VARCHAR(50) |
| 密码 | VARCHAR(255)，bcrypt 哈希存储 |

**流程**：
1. 管理员输入用户名密码
2. 服务端校验后返回 JWT token
3. 前端存储 token，后续请求携带
4. Token 有效期 24 小时

**错误处理**：
- 用户名不存在：返回"用户名或密码错误"（不具体提示哪个不对）
- 密码错误：同上
- 账号已禁用：返回"账号已被禁用，请联系管理员"

##### 2.8.3 账号管理

| 功能 | 说明 |
|:---|:---|
| 管理员列表 | 展示所有管理员账号 |
| 新增管理员 | 填写用户名、密码、显示名 |
| 修改密码 | 需输入原密码 |
| 启用/禁用 | 禁用后无法登录 |
| 删除管理员 | 至少保留一个管理员 |

### 三、非功能性需求

#### 3.1 安全性

| 要求 | 说明 |
|:---|:---|
| 密码存储 | bcrypt 哈希，不使用明文或 MD5 |
| 认证方式 | JWT Token，24h 过期 |
| 文件上传 | 限制类型 pdf/docx/xls/xlsx/jpg/png，校验 MIME 和文件头魔数 |
| 文件大小 | 单文件最大 50MB |
| SQL 注入 | 通过 ORM 参数化查询 |
| 敏感配置 | .env 文件不提交 Git |

#### 3.2 性能

| 要求 | 说明 |
|:---|:---|
| 列表接口 | 必须分页，不允许全量查询 |
| 大字段 | ocr_raw_text 默认不返回，仅详情接口按需查询 |
| LLM 调用 | 异步执行，不阻塞 API 响应 |
| 报表查询 | 大数据量下考虑缓存，不实时全量计算 |

#### 3.3 可用性

| 要求 | 说明 |
|:---|:---|
| 服务端无状态 | 支持水平扩展 |
| 数据库迁移 | 使用 Alembic，可回滚 |
| 操作审计 | 所有写操作记录到 audit_log |
